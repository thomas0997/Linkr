Guess The Link — Full Project Notes
What is it?
A single-player web-based puzzle game inspired by "4 Pics 1 Word" and "Guess The Link." The player is shown 3 images per question and must guess what they all have in common — the "link."
Example: Image of peas + sole of a shoe + meat shop → Answer: Capital Cities (Brussels, Seoul, Delhi)

How The Game Works

Game progresses level by level, unlocked linearly
Each level has multiple questions
Each question has 3 images and one correct answer
Questions are the same for everyone (pre-generated, not random per session)
Player gets a text input box to type their guess
Based on how many tries it took, they earn points and coins

Spring Boot is like Flask in Python — it turns your Java code into a running web server. You annotate a method and it handles HTTP requests.
Thymeleaf is like Jinja2 — it lets Spring inject Java data directly into HTML before sending it to the browser. Minimal JS needed because the server handles most logic.

Database Tables
players — username, coins, current level, current question
questions — id, image URLs (3), answer, hint, level number
levels — level number, total questions
progress — player id, question id, tries used, points earned, completed or not

Java Classes
Model classes (your OOP):

Question — holds image paths, answer, hint, level
Level — holds level number, list of questions
Player — holds username, coins, current level/question
GuessResult — holds whether guess was correct, points earned, coins earned

Service classes (your logic):

GameService — handles guess submission, scoring, coin calculation, level unlocking
PlayerService — manages player progress, coin deduction, coin addition
QuestionService — fetches questions from DB by level

Controller classes (Spring Boot, handles HTTP):

GameController — serves game pages, receives guesses, returns results


How Gemini Fits In

You write a prompt telling Gemini what kind of questions to make
Gemini generates question sets — 3 image descriptions + answer + hint
You run this once, store results in PostgreSQL
Everyone plays the same pre-generated questions
Gemini is not called during gameplay, only during question generation


How a Round Works
Player visits /game
→ Spring fetches current question from DB
→ Thymeleaf renders 3 images + input box
→ Player types a guess → JS sends it to Spring
→ GameService checks if correct
→ If correct: calculate points/coins, save progress, load next question
→ If wrong: increment try count, let them guess again
→ If tries > 10: auto-fail, move to next question

How Hints Work
Player clicks "Use Hint" button
→ JS sends request to Spring
→ PlayerService checks if player has ≥ 2 coins
→ If yes: deduct 2 coins, return hint text from DB
→ Thymeleaf displays hint on page
→ If no coins: show "Not enough coins"
